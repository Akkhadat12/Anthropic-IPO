# Independent QA handoff — Anthropic IPO web story

**Scope:** Test the *new* production build on branch `research-ipo-financials-models-2026`, not the historical `main` site. Read [README.md](README.md), [WORKFLOW_STATUS.md](WORKFLOW_STATUS.md), [02_RESEARCH_AND_ANALYSIS.md](02_RESEARCH_AND_ANALYSIS.md), [03_STORY_STRUCTURE.md](03_STORY_STRUCTURE.md), and [04_BUILD_WEB.md](04_BUILD_WEB.md). The builder supplies exact public Vercel production URL and deployed commit before QA starts. A preview URL, localhost, or old `main` URL is not sufficient. QA is performed by an independent agent/person, not self-approved by the builder.

## Entry and identity checks

1. Open the production URL in a clean browser without login. Confirm it shows the new “capacity ledger” story, all nine stops, current sources/caveats, and the exact deployed commit in build notes. Verify the site is reachable after a hard reload and on phone width. Record timestamp, browser/device/viewport, URL, and commit.
2. Compare the deployed source data and visible claims to the repository commit and [references/chart-data.csv](references/chart-data.csv). If an S-1 became public since 29 September 2026, flag the research package as stale rather than silently updating a single chart.
3. Confirm the builder produced one Thai `06_SCENE_RATIONALE` Google Doc or genuine `.docx` in the owner Drive folder, with exact link and screenshots of finished scenes. The rationale must describe the actual build, not merely repeat 04.

## Interaction and behavior matrix

- Click every primary target and confirm its **exact destination** in the map in 04; verify the route from `cover` through `close` and explicit restart. No click may silently do nothing or unexpectedly advance two stops.
- At each scene, test Spacebar once and several rapid repeats; confirm one coherent transition per intended advance, no skipped scenes, no stuck camera, and a stable final state. At `close`, Spacebar must not auto-loop. Test `R` from the middle of a transition and from an open overlay; it must return to a stable cover.
- Open Sources/caveats from each scene; verify a working direct source link, source type, caveat, keyboard focus, Escape close, and return to the same scene. Spacebar inside an overlay must not advance. Test all in-scene toggles/gates and each scenario selector; selected state must be understandable without animation.
- Test a touch device/phone portrait and mouse/keyboard desktop. Check visible targets, focus indicators, semantic labels, no hover-only essential meaning, and tap area. Test reduced-motion OS setting: same facts, route, and final states, with motion minimized. Test reload and direct landing if supported.
- Check 16:9 recording at common laptop resolution and full-screen. No visible Thai, source-overlay text too small to read, hidden critical data, unsafe edge placement, unexpectedly moving hold state, or performance stalls that harm narration.

## Evidence and production review

- Reopen each linked source. Verify source URLs and displayed facts against 02's claim ledger; reject a citation that merely points to a homepage. Check internal screenshot/asset use against the exact files in `references/` and listed official source pages.
- Inspect the built site for fake Anthropic/SEC marks, fabricated prospectus excerpts, invented executives/facilities, unsupported stock price, or promotional language that outruns evidence. The private Series H $965B post-money valuation must not look like an IPO price.
- Verify every number's period, unit, comparator, provisional status, and type. Specifically check that 2025 net loss is not labeled cash burn, that announced compute commitments are not annual cash outflows, and that independent benchmark task costs are not provider gross margin.
- Check the public production URL, not just preview. Confirm no authentication, no broken assets, no obvious console/runtime error, and that the deployed commit/version matches build notes. The old `main` production URL and previous QA captures are irrelevant for this pass.

## Report, fixes, and exit

Write `07_WEB_QA_REPORT.md` on this branch with: tested URL/commit/time, environments, scene screenshot paths or links, trace of every interaction, evidence/asset audit, and findings. Each finding needs an ID, severity (`blocker`, `major`, `minor`), exact scene/viewport, expected vs observed, screenshot/browser evidence, owner, and retest status. Keep unresolved findings visible. Mark `WORKFLOW_STATUS.md` `QA_FAIL` if any blocker or major failure remains; return findings to the builder for correction. After a new production commit, retest the affected paths and regression-critical scenes, record the new exact URL/commit, and only then mark `QA_PASS`. Do not reuse old screenshots or assume a source-code fix reached production.
