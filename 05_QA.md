## Evidence and report format

Test the **actual final public production URL in a real browser**, not localhost or an authenticated preview. Capture settled Cover, Scenes 1–6, and Closing at the primary 16:9 recording viewport; capture each distinct narrow phone layout; capture representative transitions, click feedback, and any overlays that could clip content. Screenshot paths must be stable in the repository or durable owner-accessible storage and show the final published version, never fabricated mockups. Inspect the page live as well as the screenshots at normal viewing scale. Hide each scene title temporarily during review to test whether the meaningful visual still carries the idea. Revisit after fixes and recapture changed states.

For every check below, enter in **`07_WEB_QA_REPORT.md`**: exact final URL, test date, scene/scope and state, viewport/capture scale, expected result, observed result, **PASS / FAIL / PARTIAL**, a real screenshot link or precise browser observation, severity for material failure, required correction, and post-fix retest result. A passing build command alone never passes visual or factual acceptance. No material FAIL may remain at delivery.

## 1. Evidence and factual integrity

**Whole site:** Recheck all time-sensitive claims against the sources at publication. Open any newly public Anthropic S-1; if present, reconcile the 2025 Reuters figures and multiyear obligations, then update the canonical research, chart data, and web copy. Expected: every date, basis, unit, qualifier, and source status matches [02's claim ledger](02_RESEARCH_AND_ANALYSIS.md) and [chart-data.csv](references/chart-data.csv). Evidence: a number/label inventory with the source URL and screenshot of each visible numeric state. **FAIL** if FY2025 recognized revenue is drawn as the same basis as May 2026 annualized pace; if Reuters-reported data is called a personally audited public filing; if preliminary adjusted profit is called GAAP/net profit or FCF; if $518B is shown as 2027 cash, added to the AWS >$100B, or depicted as already spent; or if a priced/listed IPO is implied without a new verified filing.

**Scene 3:** Verify Anthropic's “up to 30% less per task” Sonnet 5.5 claim is labeled as a company test and never converted into a measured corporate margin improvement. **FAIL** if the graphic implies a known training/inference split or exact cost per Claude task.

**Scene 6 and Closing:** Verify rival model names and any pricing are current from [OpenAI](https://openai.com/index/gpt-6-astra/) and [Google](https://ai.google.dev/gemini-api/docs/pricing). The proof checklist must distinguish observation from scenario. **FAIL** if a model “wins” from a non-comparable token price or if a justified IPO valuation is invented.

## 2. Story and thesis integrity

Expected sequence: Cover → financial-basis puzzle → customer task/revenue route → compute-per-task hinge → preliminary operating signal → capacity/capital clock → competition and proof gates → conditional close. Evidence: record the actual scene identifiers and settled screenshots in viewer order, compare each against [03_STORY_STRUCTURE.md](03_STORY_STRUCTURE.md). **FAIL** if a major beat is missing, if two beats repeat the same claim without new explanatory work, if the positive operating signal is suppressed, or if the capital requirement is used to claim inevitable failure. The final frame must ask whether verified margins and cash can support continued frontier investment, not issue a buy/sell conclusion.

## 3. Scene composition and clipping acceptance

For **every** beat, inspect the settled 16:9 page, a phone-width page, and relevant transition frames. Check first-glance focal subject; hide the title and check whether meaningful objects/relationships remain. Inspect alignment, visual weight, spacing, negative space, safe-area use, z-order, attached labels, connector endpoints, crop intent, and visible word count (target at most 12 words beyond necessary chart values/units/basis labels; justify exceptions). Count words rather than shrinking prose. **FAIL** accidental viewport/mask/browser-chrome clipping, lost identity or qualifiers, image stretching, rough cutouts, controls off-screen, horizontal overflow, overlaps, awkward tangencies, weak first-glance hierarchy, decoration that outranks evidence, or a title-only empty stage. An intentional crop passes only with a documented scene-specific reason and preserved evidence-bearing detail at both widths.

- **Cover:** Expected first screen at the public URL: recognizable Project Rainier aisle/racks and its human scale, a short central question, and a meaningful entry target. Compare the actual displayed image with [the stored interior photo](references/project-rainier-interior.png) and [AWS original](https://assets.aboutamazon.com/7d/36/614bf5354a3a9d570976a3db3a6e/interior-rainier.png). Screenshot the settled cover, phone arrangement, and first transition. **FAIL** if the facility is a generic or invented substitute, if a crop reduces it to unrecognizable texture, if people/racks are distorted or covered by title, if the cover is only text, or if entry is hidden. Verify the site does not suggest Anthropic owns the AWS facility.
- **Scene 1:** Expected two visibly separated bases with attached period and unit: FY2025 actual results reported by Reuters versus May 2026 company-stated run-rate. Screenshot both viewports and reveal. **FAIL** if a connector/animation suggests one continuous growth series, if `>` or “run-rate” disappears at phone width, or if historical loss visually vanishes behind current pace.
- **Scene 2:** Expected paid customer task and distinguishable direct/API/cloud routes leading to paid use. Screenshot settled route and every selectable route state if interactive. **FAIL** disconnected route endpoints, invented channel proportions, fake product UI, invented customer marks, or an interactive route that silently advances the story.
- **Scene 3:** Expected price per useful task and compute per task simultaneously legible, with frontier training separate from the task-level mechanism. Screenshot settled and explanatory movement. **FAIL** if the conceptual relationship looks like a measured bar chart, if a task cost is invented, if a subject/label is clipped after narrow rearrangement, or if the company test claim appears as audited margin data.
- **Scene 4:** Expected FY2025 operating loss and Q2 2026 preliminary *adjusted* positive signal presented as separate observations with attached basis and period. Screenshot both viewports and transition. **FAIL** a continuous zero-crossing line, an unlabeled “profitable” result, missing “preliminary/adjusted,” or a layout that makes the Q2 signal look like FY2025 GAAP net income.
- **Scene 5:** Expected recognizable AWS Project Rainier campus plus separate AWS >$100B/10-year and Reuters-reported ~$518B future-year commitment descriptions. Compare the rendered subject with [stored exterior photo](references/project-rainier-exterior.png) and [AWS original](https://assets.aboutamazon.com/50/19/309b104648e1b00c5c7dec3fdc54/projectrainier-exterior.png). Screenshot settled 16:9, phone, and commitment reveal. **FAIL** a generic data-center replacement, unintended campus crop/stretch, a photo wallpaper obscuring labels, missing time horizon, added commitment totals, or proportional annual cash bars invented from unknown schedule.
- **Scene 6:** Expected competition/customer choice to lead to four readable proof gates: recognized revenue quality, GAAP margins, cash after compute investment, and commitment schedule. Screenshot both widths and every interactive gate. **FAIL** a logo contest without economic meaning, a missing gate, clipped labels/touch targets, or a decorative diagram that cannot be understood when its title is hidden.
- **Closing:** Expected two linked but conditionally converging clocks, stable for a spoken close, and a discoverable return behavior. Screenshot both widths and return transition. **FAIL** a guaranteed/complete convergence depiction, a price target, a title-only screen, or controls hidden near the edge.

Inspect adjacent settled scenes as a sequence. The visual progression should move from real capacity to financial bases, a task, economics, evidence, capital, and a future test. **FAIL** unexplained repeated card arrangements, a visual shift that reverses the argument, or a transition that hides the new focal subject. Purposeful sparse or repeated structures may pass with a specific reason recorded in the report.

## 4. Real asset and image integrity

The cover interior and Scene 5 exterior are **essential real-image components**. Expected: accurate Project Rainier depictions from the saved source files or a documented more accurate replacement of the same subject, locally hosted by the public site, with original URL and depicted subject in build notes. Verify the image actually renders after refresh and on phone, both settled and in transition. Check crop, masks, edge quality, proportions, resolution, overlays, and factual identity. **FAIL** invented likeness/mark, generic server room, broken image path, unintended clipping, stretched aspect ratio, cutout halo, image/label collision, or silently removed essential identity. If a replacement is sourced independently, verify its original source, actual depiction, working public asset, and inventory update; a better image need not match the original `references/` file exactly. Flag a photo collage or overloaded scene when the authored relation would explain the claim more clearly.

## 5. Palette, visual communication, and polish

Inspect the cover and every settled scene at 16:9. Compare the builder's documented browser comparison of **two materially different viable color directions** on a representative composed scene with the final design. Record chosen stage, type, and accent hex values in the QA report and judge foreground contrast, recording clarity, and whether the stage supports the subject rather than becoming the story. **FAIL** an untested palette choice, busy or low-contrast stage, generic AI backdrop, repeated glowing-node décor, identical card layouts, empty recolored scenes, excessive effects, or meaning dependent on color alone. Run a first-glance focal test for each beat without reading the brief; report if attention goes to decoration, incidental labels, or empty space rather than the intended subject. Record why any unusual asymmetry, density, sparse frame, oversized subject, or tight intentional crop works for this beat.

## 6. Presenter, recording, and interaction coverage

Check the practical full-screen **16:9 YouTube recording frame** at the owner's capture scale, including browser chrome, scaling, letterboxing, and capture crop. Expected: cover first, no presentation rail/dots/arrows/page numbers, readable subjects and labels, English-only minimal site copy, and a still hold state of arbitrary duration after each entrance. **FAIL** hidden evidence/control in the actual captured frame, an auto-advance timer, ongoing motion competing with speech, or a scene that cannot be held.

Enumerate and test every meaningful click target with actual destination and feedback:

- Cover facility/question entry → Scene 1.
- Scene 1 paired financial signal → Scene 2.
- Scene 2 paid-task/output focal region → Scene 3; route exploration stays on Scene 2.
- Scene 3 task-economics hinge → Scene 4.
- Scene 4 separated evidence/question region → Scene 5.
- Scene 5 campus/commitment region → Scene 6.
- Scene 6 final proof-gate region → Closing.
- Closing focal return region, if implemented → Cover.

From **Cover, Scene 3, and Closing**, press **Spacebar** and **R**, recording expected and observed destinations. Space advances exactly one beat from Cover through Closing and does nothing further at Closing; R returns to Cover from anywhere. Click, Space, and R during transitions and in rapid repetition; expected: no double advances, skipped scene, stuck transition, duplicated handler, or invalid state. Test touch and keyboard focus, visible feedback, accessible names for controls, and escape from any source overlay. **FAIL** ambiguous or undiscoverable targets, scene skip, broken focus, or missing keyboard shortcut.

## 7. Motion, responsive behavior, and accessibility

Inspect actual transitions and selected explanatory movement, plus settled frames. Expected: visible purposeful motion at scene changes and selected relationships; it helps orientation or understanding, then ends. In `prefers-reduced-motion`, all content and navigation remain usable without essential facts hidden in an animation. **FAIL** no intentional motion, flashes/jank, perpetual decorative movement, motion that implies a false measured trend, automatic timing pressure, or reduced-motion mode that skips required information.

At a narrow phone viewport, test every beat after load, navigation, resize, and refresh. Expected: coherent reordered relationships, readable short labels, large enough touch targets, focus visibility, no horizontal page overflow or missing images. **FAIL** accidental cropping, overlapping labels, missing qualifiers, off-screen controls, or broken navigation. The phone composition may differ from 16:9 but must preserve each scene's critical relationship listed in [04](04_BUILD_WEB.md).

## 8. Technical, deployment, and adversarial checks

Run the production build and load the **exact final production URL** in a clean browser context without the builder's login. Expected: finished Cover first, working local images and chart data, no uncaught runtime errors, material console warnings, missing assets, or transition-blocking freezes. Refresh, directly reopen the URL, navigate the full sequence repeatedly, resize during use, and trigger inputs quickly. Watch for event-listener or memory growth causing later navigation to stutter. **FAIL** a private/authenticated site, preview-only URL, stale deployment, different URL handed to the owner, material runtime failure, broken direct reopen, or performance that visibly undermines presentation. Record the public URL and browser/version in `07_WEB_QA_REPORT.md`.

Deliberately try to falsify completion after each material fix: recheck the affected settled and transition states at both widths, then visit adjacent scenes and repeat the interaction path. A fix that introduces a new factual, visual, responsive, or interaction regression is not a pass.

Open the saved DOCX and verify Thai glyphs, one mobile-readable reading column, legible settled screenshots and captions, short paragraphs, and working source links. Compare its thesis, URL/date/navigation, real Cover, each Scene 1–6, and Closing against the final published site. Each section must explain viewer takeaway, why it occurs there, the actual objects/real images/composition/interaction, evidence and caveats, original source URLs, and material changes from the plan. **FAIL** if it is missing, unreadable, stale, missing a scene, using planned rather than actual screenshots, or materially inconsistent with the live site. An MD scene list is not a substitute.

Delivery fails if the report or stable evidence is absent, if material failures remain, or if the production URL is not public and accessible without login. Return links to both the report and the final commit.
